# ADR-0004: Interaction & Config Consistency Refinements

**Status:** Accepted（Deferred 第 2 项中的 3C 批量化/忽略冷却与模板占位说明已由 ADR-0005 实现；第 1 项快速模式激进版与第 2 项中的归档「保持原样」仍开放）
**Date:** 2026-08-19
**Supersedes:** none（SKILL.md 指令级修订，不取代既有 ADR 决策；快速模式此前仅零散写在 SKILL.md/description 中，未入 ADR）

## Context

SKILL.md 分析（2026-08-19）发现四类一致性与体验问题：

1. **快速模式几乎不省时**：原定义只跳过步骤 6（细化与预估），但最耗时的步骤 4 逐条重要/紧急两问（2×任务池大小）原样保留，与"时间紧"的意图矛盾。
2. **「重要沿用原判断」被步骤 4 单方面违反**：步骤 2 选项 b 与步骤 3C 承诺延续任务沿用旧的重要判断，步骤 4 却对任务池每一条无条件重问两个问题。
3. **config 参数与正文脱节**：`default_language`、`todo_filename` 全程未被正文读取（死参数）；`top_n` 被正文与 description 硬编码为 3。
4. **同日重跑无幂等处理**：今日文件已存在时步骤 7 会静默覆盖当天数据。

## Decisions

1. **快速模式重新定性**：步骤 1/2/3/7 照常（数据管理环节不可省）；步骤 4/5 合并为一次批量挑选——一次性列出任务池（标注来源），用户直接圈出「今天必做」，超过 top_n 按圈选顺序取前 top_n；步骤 6 整节跳过，时间预估写 `未预估`。定义集中放在「核心流程」开头，步骤 4/5 各自只留执行细节。
2. **延续任务沿用重要判断**：来源为「昨日收尾（步骤 1）/ 归档归入（步骤 2 选项 b）/ 跨天延续（步骤 3C）」的任务，其重要判断直接从原文件四象限总览沿用，只重问紧急；用户称态势无变化时两问都跳过，直接进总览确认。
3. **config 接线**：正文与 description 的 `todo.md`、`Top 3`、默认语言字面量改为 `{todo_filename}`、`Top {top_n}`、并按 `default_language` 决定对话语言；保留配置表作为 agent 的速查缓存，config.json 仍为单一事实源。
4. **同日重跑幂等**：生成前检测今日文件是否存在，存在时让用户选择「覆盖 / 在原文件上追加更新 / 取消」。

## Rationale

- 快速模式的目标是压缩交互不是压缩流程；批量圈选把 2×N 次提问压成 1 次，同时保留四象限输出的完整性（圈选条目按是否提及截止归①/②，未圈选归④，注明"快速模式"）。
- 沿用旧判断避免同一判断被重复征询，与「做减法」人设一致；旧判断有可回溯的记录载体（每日文件四象限总览）。
- ADR-0003 已声明 config 为配置单一事实源，本次把正文与 description 的硬编码对齐到该事实源，消灭死参数。
- 幂等处理防止同日二次运行破坏当天数据，成本仅一次文件存在性检查。

## Deferred

- 快速模式是否进一步激进（跳过步骤 4 直接挑 3 条）——暂不采纳，避免四象限总览内容缺失。
- 步骤 3C 批量化与「已忽略」冷却、归档选项增加「保持原样」、模板 `{星期}` 占位说明——留待观察实际使用后再定。
