## 1. 背景与定位

### 1.1 动机

读完书后缺少结构化自我提问，传统读后感容易流于表面。

### 1.2 目标

一个**全局可用**的阅读后深度反思工具（`/book-grill`），提供三项核心功能：

- **结构化提问**：按书类型自适应的四阶段递进提问，动态生成问题，倒逼深度思考
- **自动笔记生成**：对话结束后生成结构化读后感（Phase 2 增加对话中实时札记）
- **阅读史累积**：笔记持久化存储，形成可回溯的个人阅读史

**适用范围**：任何支持斜杠命令 + skill 加载的 Agent 环境（如 OpenCode、Claude Code、Cursor 等），不绑定特定平台。

### 1.3 核心差异声明

> book-grill 不做 grill-me 能做的事。grill-me 是通用拷问工具，book-grill 是阅读垂直领域的深度反思系统。两者互补而非替代。详见 [§2 定位声明](#2-定位声明)。

---

## 2. 定位声明

book-grill 是阅读垂直领域的深度反思工具，核心差异化在于**领域知识嵌入 + 结构化笔记产出**。

长期护城河：`~/.local/share/book-grill/` 的阅读史数据——grill-me 没有持久化层，这是根本差异。随着 Phase 3/4 的跨书对比和阅读演进史功能，差异化将持续加深。

## 3. 核心设计决策

| 决策项       | 选择                                                                                            | 理由                                      |
| ------------ | ----------------------------------------------------------------------------------------------- | ----------------------------------------- |
| 触发方式     | `/book-grill <书名>`                                                                            | 语义清晰，与 `/grill-me` 自然区分         |
| 安装范围     | 全局 skill（`~/.agents/skills/book-grill/`）                                                    | 位置无关                                  |
| 书类型处理   | LLM 初步推断 + 开场向用户确认，**不追求精准分类**                                               | 分类天然模糊，用户共识比分类正确更重要    |
| 提问策略     | 按书类型自适应（4 类独立模板），**动态生成问题 + 备选兜底**，阶段转换由目标达成驱动              | 动态提问比固定问题序列更自然、更有针对性  |
| 背景收集     | LLM 不熟悉该书时，从用户处快速收集背景信息                                                       | 动态提问需要上下文，否则问题泛化无针对性  |
| 知识锚定     | LLM 每轮最多一次引入外部相关知识制造思考角度（非灌输）                                           | 丰富追问维度，但严格受控防止变成知识讲座  |
| 笔记格式     | 统一 frontmatter（文件头部元数据）+ 结构化章节                                                  | 可汇总、可搜索、可回溯                    |
| 笔记存储     | `~/.local/share/book-grill/notes/`（Phase 2 增加 `notepads/`）                                  | 长期累积，形成个人阅读史                  |
| 读后感命名   | `<书名>-YYYY-MM-DD.md`                                                                          | 避免覆盖历史版本，支持多轮对话累积        |
| INDEX.md     | 按需生成（`/book-grill --index`），不自动维护（Phase 2）                                        | 避免 LLM 自动更新 markdown 表格时格式破坏 |
| 待探索追踪   | 用户说"pass"/"不知道"时标记为待探索项，读后感中汇总                                             | 阅读垂直领域的深度功能                    |
| 信息获取     | Phase 1 不使用 websearch；背景信息从用户补充；LLM 自身知识受控调用                                | 减少错误面，用户已提供书名即足够          |
| **分类依据** | **参考《如何阅读一本书》（莫提默·艾德勒）的"实用性 vs 理论性"框架，按"阅读方法"而非"学科"分类** | **确保分类服务于阅读反思，而非学科归类**  |

**阅读状态适配推迟到 Phase 3**。Phase 1 开场只确认书类型，不区分完整阅读/部分阅读/重读/听书。

### 3.1 角色与语气

book-grill 的 LLM 扮演**谆谆善诱、知识渊博的资深读者**——像一个读完同一本书后想和你聊聊的朋友，而不是一个拿着评分表的考官。

**语气**：温和、好奇、引导。

| 说 | 不说 |
|----|------|
| "这个角度有意思——不过你再想想，作者在这里是不是还有一层意思？" | "你漏掉了一个重点" |
| "你提到了X——这让我想到书里另一个地方也说了类似的事，你觉得两者有什么联系？" | "请比较X和Y" |

**核心原则**：不评价，只追问。不说"答得好"也不说"答错了"——评价会打断用户的思考流，追问才能推动深度。

**设计意图**：同样的提问内容，语气不同会产生完全不同的对话体验。角色定义确保 LLM 的追问是"邀请思考"而非"考核验收"，这是 book-grill 与通用拷问工具的体验差异之一。

## 4. 书类型自适应提问

> **本章要点**：book-grill 针对不同的书类型使用完全不同的提问策略，这是核心差异化所在。

### 4.1 书类型分类（软分类）

**分类天然模糊**，无书可完全归入单一类别。这里列出的四种类型是 LLM 的**初始推断依据**，开场时会向用户确认，用户可随时纠正。LLM 不追求分类正确，而是追求和用户"从什么角度聊这本书"达成共识。

> **分类依据**：本分类参考《如何阅读一本书》（莫提默·艾德勒）的框架，将书籍按"阅读方法"而非"学科"进行分类：
>
> | 类型       | 对应概念             |
> | ---------- | -------------------- |
> | fiction    | 想象文学             |
> | nonfiction | 理论性书籍           |
> | biography  | 历史书中的人物聚焦型 |
> | technical  | 实用性书籍           |

| 类型         | 检测信号                   | 提问侧重                                   | 包含                       | 不包含                     |
| ------------ | -------------------------- | ------------------------------------------ | -------------------------- | -------------------------- |
| `fiction`    | 小说/科幻/文学/戏剧/诗歌   | 叙事结构、人物弧光、写作手法、主题隐喻     | 虚构叙事、想象文学         | 纪实文学、历史记录         |
| `nonfiction` | 经济/历史/科学/哲学/方法类 | 核心论点、论据检验、逻辑链、应用价值       | 理论性书籍、论说类作品     | 传记、回忆录、技术教程     |
| `biography`  | 传记/回忆录/自传、人物名   | 人物决策、历史语境、作者立场、经验教训     | 人物传记、回忆录、自传     | 历史书（非人物聚焦）、小说 |
| `technical`  | 教程/指南/实战/精通        | 前置知识、概念清晰度、教学有效性、实操应用 | 技术教程、工具方法、自助类 | 纯理论科学、哲学思辨       |

**边界处理原则**：

- 历史小说（如《三国演义》）→ LLM 问用户"你更想从哪个角度聊？"，使用用户选择的对应模板
- 纪实文学（如《冷血》）→ 同上，让用户选择 fiction 或 nonfiction 视角
- 回忆录式散文 → `biography`，侧重个人经验和语境
- 用户不同意分类 → 直接纠正，LLM 切换到对应模板

**核心原则：分类是起点，不是终点。**

### 4.2 书类型问题模板

> 以下四类独立模板根据书类型按需加载。LLM 确认书类型后，读取对应模板文件进入提问阶段。
>
> **模板结构**：每个模板文件包含三部分——**阅读策略**（该类型的专业阅读指导）、**四阶段提问框架**（每阶段含阶段目标、提问方向、追问示例、备选问题、进入下一阶段条件）。LLM 基于提问方向动态生成问题，备选问题仅在 LLM 不熟悉该书时使用。

#### Fiction（小说）

**定义**：虚构类作品，通过想象构建的世界。对应《如何阅读一本书》中的"想象文学"。

**包含**：小说、科幻、文学、戏剧、诗歌
**不包含**：纪实文学、历史记录、传记

**阅读策略**：小说的深层意义藏在叙事技术里。引导时关注叙事视角（谁在讲故事？不可靠叙述者？）、时间线操控（为什么这样安排？）、人物动机（嘴上说的和实际做的差距）、留白与象征（作者故意没写的是什么）。

```
A 理解确认
  阶段目标：确认用户是否准确把握故事的核心内容与叙事结构
  提问方向（根据用户回答选择，不固定顺序）：
    - 情节线：主要故事是什么？有没有特别意外的支线？
    - 人物：主人公的决策轨迹你认同吗？有没有不合理的行为？
    - 叙事：作者在叙事手法上有什么特别之处？（视角/时间线/语言风格）
  备选问题（LLM 不熟悉该书时可用）：
    - 故事的主要情节线是什么？有没有哪条支线让你觉得特别意外？
    - 主人公的决策和成长轨迹你认同吗？有没有什么行为让你觉得不合理？
    - 作者在叙事手法上有什么特别之处？
  进入 B 条件：用户能准确描述核心情节，且对人物动机或叙事手法有基本理解

B 批判分析
  阶段目标：引导用户挖掘文本的深层主题和作者意图
  提问方向：
    - 深层主题：这个故事在探讨什么？通过情节传达了哪些关于人性/社会的观点？
    - 作者意图 vs 读者感受：作者想表达的和你感受到的一致吗？
    - 替代可能：如果换一个不同的结局/视角/设定，故事的核心信息会变吗？
  备选问题（LLM 不熟悉该书时可用）：
    - 这个故事在探讨什么更深层的主题？它通过情节传达了哪些关于人性/社会的观点？
    - 如果换一个不同的结局，你觉得故事的核心信息会变吗？
  进入 C 条件：用户能超越字面理解，触及主题层面

C 个人共鸣
  阶段目标：帮助用户发现书中内容与自身经历/情感的连接
  提问方向：
    - 人物投射：有没有哪个角色让你联想到自己或身边的人？
    - 经验共振：书中的什么情境让你想到了自己的某段经历？
    - 认知触发：读完之后，对哪些以前没想过的问题开始有了自己的看法？
  备选问题（LLM 不熟悉该书时可用）：
    - 故事中有没有哪个人物让你联想到自己认识的人？或者让你想到自己的某段经历？
    - 读完这个故事，你对哪些以前没想过的问题开始有了自己的看法？
  进入 D 条件：用户建立了至少一个书中内容与自身的连接

D 超越书本
  阶段目标：引导用户将阅读收获延伸到更广的思考或行动
  提问方向：
    - 认知迁移：这本书改变了你的什么看法？这种改变会影响你未来的什么选择？
    - 普遍化：如果这个启示被广泛应用，世界会因此变得更好还是更坏？
    - 行动指引：你会因为这本书做任何不同的事吗？
  备选问题（LLM 不熟悉该书时可用）：
    - 这本书带给你的认知变化，会如何影响你未来的思考或行动？
      → 追问方向：如果这个启示被广泛应用，世界会因此变得更好还是更坏？
```

#### Nonfiction（非虚构）

**定义**：非虚构类作品，记录真实事件、观点或知识。对应《如何阅读一本书》中的"理论性书籍"（历史、科学、哲学、社会科学等）。

**包含**：历史、经济、科学、哲学、社会科学、论说类作品
**不包含**：传记、回忆录、技术教程、虚构作品

**阅读策略**：非虚构的核心是论证质量。引导时关注方法论局限（结论依赖什么方法？）、因果 vs 相关（是真的因果还是只是相关？）、样本与偏差（论据来自什么样本？）、隐含假设（没明说但必须成立的前提？）、可证伪性（作者考虑了哪些反证？）。

```
A 理解确认
  阶段目标：确认用户是否准确把握书的核心论点和论证逻辑
  提问方向（根据用户回答选择，不固定顺序）：
    - 核心论点：这本书的主张是什么？作者在试图解决什么问题？
    - 论据结构：作者用了哪些论据？最有说服力的是哪个？最弱的呢？
    - 论证逻辑：能用自己的话复述作者的推理链条吗？
  备选问题（LLM 不熟悉该书时可用）：
    - 这本书的核心观点/主张是什么？作者在试图解决什么问题？
    - 作者用了哪些论据来支撑这个观点？你觉得最有说服力的是哪一个？
    - 你能用自己的话复述一下作者的论证逻辑吗？作者的叙事方式（如果有的）对理解有什么影响？
  进入 B 条件：用户能准确复述核心论点，且理解论证的基本结构

B 批判分析
  阶段目标：引导用户审视论证质量、发现隐含假设和对立观点
  提问方向：
    - 隐含假设：论证中有没有没明说但必须成立的前提？如果前提不成立呢？
    - 视角局限：作者的立场可能忽略了什么？有没有选择偏差？
    - 对立观点：对于这个问题，有没有其他合理的解释？作者是如何回应的？
  备选问题（LLM 不熟悉该书时可用）：
    - 作者的论证中有没有隐藏的假设？他的视角可能忽略了什么？
    - 对于这个问题，有没有其他合理的解释或对立观点？作者是如何回应的？
  进入 C 条件：用户能指出论证的至少一个薄弱环节或隐含假设

C 个人共鸣
  阶段目标：引导用户将书中论点与自身认知和经验对照
  提问方向：
    - 认知改变：这本书改变了你对这个议题的哪些既有认知？
    - 经验印证/冲突：你的个人经历是支持还是反驳作者的观点？
    - 行为改变：你会因为这本书而改变什么实际行为或决策方式吗？
  备选问题（LLM 不熟悉该书时可用）：
    - 这本书改变了你对这个议题的哪些既有认知？
    - 你会因为这本书而改变什么实际行为或决策方式吗？
  进入 D 条件：用户建立了书中论点与自身经验/认知的连接

D 超越书本
  阶段目标：引导用户将认知变化延伸到更广的领域或更深的行动
  提问方向：
    - 认知迁移：这本书改变了你的什么看法？这种改变会影响你未来的什么选择？
    - 回溯反思：重新回答 A 阶段的问题，你的答案改变了吗？是什么让你改变？
    - 延伸应用：这个论点/方法可以应用到其他什么领域？边界在哪？
  备选问题（LLM 不熟悉该书时可用）：
    - 这本书带给你的认知变化，会如何影响你未来的思考或行动？
      → 追问方向：重新回答第一阶段的问题，你的答案改变了吗？是什么让你改变？
```

#### Biography（传记）

**定义**：记录真实人物生平的作品。对应《如何阅读一本书》中的"历史书"，但因其独特的人物聚焦视角而单独分类。

**包含**：传记、回忆录、自传、人物聚焦型历史作品
**不包含**：纯历史书（非人物聚焦）、虚构作品

**为什么单独分类**：传记阅读需要同时关注"人被时代塑造"和"人主动选择"两个维度，涉及作者立场、史料选择性、历史语境等独特问题，无法被 nonfiction 模板覆盖。

**阅读策略**：传记是人与时代的交叉叙事。引导时关注作者立场（褒贬倾向如何影响史料选择？）、美化与省略（什么被放大/淡化了？）、时代语境（自由意志 vs 时代推动）、叙事结构（时间顺序 vs 主题编排暗示什么价值判断？）。

```
A 理解确认
  阶段目标：确认用户是否准确把握传主的核心特质与关键人生节点
  提问方向（根据用户回答选择，不固定顺序）：
    - 人物画像：从这本书中，你读到的是一个怎样的人？哪些特质最突出？
    - 关键决策：他人生中哪些关键决策塑造了后来的轨迹？背后是什么驱动他？
    - 时代背景：所处的历史/社会背景中，哪些因素深刻影响了他的选择和命运？
  备选问题（LLM 不熟悉该书时可用）：
    - 从这本书中，你读到的是一个怎样的人？他的哪些特质对你触动最大？
    - 他人生中哪些关键决策塑造了后来的轨迹？如果是你，你在那个时刻会怎么做？
    - 这本书所处的历史/社会背景中，有哪些因素深刻影响了他的选择和命运？
  进入 B 条件：用户能准确描述传主的核心特质，且理解关键决策与时代背景的关系

B 批判分析
  阶段目标：引导用户审视传记的叙事立场和史料选择
  提问方向：
    - 作者立场：作者对传主是褒是贬？这种倾向如何影响叙述？
    - 美化与省略：什么被放大了？什么被淡化了？为什么？
    - 客观性边界：传记中的叙述有多少是事实，多少是作者的推测和解读？
  备选问题（LLM 不熟悉该书时可用）：
    - 作者对这个人物是褒是贬？作者的倾向是否影响了叙述的客观性？
    - 传记中是否有美化的成分？有没有什么信息被刻意弱化或省略了？
  进入 C 条件：用户能识别至少一处作者立场对叙述的影响

C 个人共鸣
  阶段目标：帮助用户将传主的经历与自身人生对照
  提问方向：
    - 自我映射：他的经历让你对自己的人生有什么反思？
    - 经验提取：书中哪些教训或经验可以应用到你的工作或生活中？
    - 时代对比：他面对的困境，在今天有对应物吗？你会怎么应对？
  备选问题（LLM 不熟悉该书时可用）：
    - 这个人的经历让你对自己的人生有什么反思？
    - 书中哪些教训或经验可以应用到你的工作或生活中？
  进入 D 条件：用户建立了传主经历与自身生活的连接

D 超越书本
  阶段目标：引导用户将阅读收获延伸到更广的思考
  提问方向：
    - 认知迁移：这本书改变了你看待"成功""选择""命运"的方式吗？
    - 历史镜鉴：这段人生/这段历史，对当下有什么启示？
    - 行动指引：你会因为这本书做任何不同的事吗？
  备选问题（LLM 不熟悉该书时可用）：
    - 这本书带给你的认知变化，会如何影响你未来的思考或行动？
      → 追问方向：这种拷问式反思方法，对你理解这个人/这段历史带来了哪些不同？
```

#### Technical（技术/工具书）

**定义**：实用型书籍，教你如何去做你想做的事情。对应《如何阅读一本书》中的"实用性书籍"。

**包含**：技术教程、工具方法、自助类、实战指南
**不包含**：纯理论科学、哲学思辨、虚构作品

**注意**：自然科学（天文、地理、物理）若侧重理论解释，归入 nonfiction；若侧重实验操作或技术应用，归入 technical。

**阅读策略**：技术书的目的是让你能做某件事。引导时关注适用前提（方法在什么条件下成立/失效？）、版本敏感（建议是否仍然适用？）、实践 vs 理论（真实项目中可行吗？）、教学有效性（作者的教学方式对读者有效吗？）、下一步（该做什么项目巩固？）。

```
A 理解确认
  阶段目标：确认用户是否准确理解书的核心教学内容和自己的知识定位
  提问方向（根据用户回答选择，不固定顺序）：
    - 知识定位：你读这本书前具备哪些相关基础？你的水平和目标读者匹配吗？
    - 核心内容：这本书主要教什么？读完之后你掌握了哪些之前不会的概念或技能？
    - 教学评估：作者的教学方式（示例/练习/讲解）你觉得有效吗？哪些地方讲得不够清楚？
  备选问题（LLM 不熟悉该书时可用）：
    - 你读这本书前具备哪些相关基础或前置知识？
    - 这本书主要教什么？它的目标读者是谁？你是否符合这个画像？
    - 读完之后你掌握了哪些之前不会的概念或技能？哪些部分是已经知道的？
    - 作者的教学方式（示例/练习/讲解）你觉得有效吗？
  进入 B 条件：用户能准确描述书的核心教学内容，且对自己的知识缺口有认知

B 批判分析
  阶段目标：引导用户评估书中技术/方法的实用性和局限
  提问方向：
    - 适用边界：书中的技术/方法在你的实际场景中真的可用吗？有什么限制？
    - 时效性：书中给出的建议有没有过时或者有争议的内容？
    - 实践差距：作者说的在真实项目中可行吗？和你的经验一致吗？
  备选问题（LLM 不熟悉该书时可用）：
    - 这本书提到的技术/方法，在你的实际场景中真的可用吗？有什么限制？
    - 书中给出的建议或最佳实践，有没有过时或者有争议的内容？
  进入 C 条件：用户能指出书中至少一个适用前提或局限

C 个人共鸣
  阶段目标：帮助用户将书中内容与实际项目/学习路径对接
  提问方向：
    - 应用计划：你打算把这本书的内容应用到什么具体项目中？第一步做什么？
    - 知识延伸：这本书让你对哪些相关领域产生了兴趣？接下来想学什么？
    - 经验对照：书中的方法和你自己之前的做法有什么不同？哪个更好？
  备选问题（LLM 不熟悉该书时可用）：
    - 你打算把这本书的内容应用到什么具体项目中？第一步做什么？
    - 这本书让你对哪些相关领域产生了兴趣？接下来想学什么？
  进入 D 条件：用户有至少一个具体的应用计划或延伸方向

D 超越书本
  阶段目标：引导用户将学习收获系统化，形成可迁移的能力
  提问方向：
    - 认知升级：这本书改变了你对这个技术领域的基本理解吗？
    - 能力迁移：学到的思维方式/方法论，可以迁移到其他什么领域？
    - 推荐视角：如果让你用一句话向同事推荐这本书，你会怎么说？
  备选问题（LLM 不熟悉该书时可用）：
    - 这本书带给你的认知变化，会如何影响你未来的思考或行动？
      → 追问方向：如果让你用一句话向同事推荐这本书，你会怎么说？（对比 A 阶段的回答）
```

### 4.3 追问差异

同一回答，grill-me 和 book-grill 的追问方向完全不同：

```
用户回答：「我觉得黑暗森林理论很有说服力」

grill-me 追问： 「你为什么觉得它有说服力？你的判断标准是什么？」
  （通用的"你为什么这样认为"模式）

book-grill 追问（fiction）： 「在《三体》的世界观里，黑暗森林是推导出来的结论还是设定前提？
  这个理论有没有改变你对宇宙中其他文明的想象？」
  （回到小说世界观内部，深入理解）

book-grill 追问（nonfiction）：「如果黑暗森林理论是一个关于人类社会的隐喻，
  它在现实中有没有对应的例子？国际关系中有类似现象吗？」
  （从书中延伸到现实世界分析）
```

### 4.4 追问策略（苏格拉底式诘问）

book-grill 的追问不是随机的，而是根据用户回答的特征进行**策略性追问**：

| 用户回答特征           | 追问策略           | 示例                                                 |
| ---------------------- | ------------------ | ---------------------------------------------------- |
| **回答模糊**（< 10字） | 要求具体化         | "你能具体说说吗？" / "你说的'X'具体指什么？"         |
| **回答泛泛**           | 要求举例           | "能举一个书中的例子吗？"                             |
| **回答矛盾**           | 指出矛盾并引导关联 | "你刚才说...，但现在又说...，这两者之间有什么联系？" |
| **回答深入**           | 横向拓展           | "这个观察很有趣，如果把它应用到另一个场景会怎样？"   |
| **回答偏离书本**       | 拉回文本           | "这个观点和书中的哪个案例有关联？"                   |
| **答案对但推理缺失/错误** | 探查推理过程   | "你是怎么推导出这个结论的？" / "你说的结论和书中论证之间，你是怎么建立联系的？" — 如果推导过程暴露误解或空洞，按"回答泛泛"或"回答矛盾"处理，不接受仅有结论而无推理的回答 |
| **手挥式回答**（"大概"/"basically"/"就是那样"） | 要求精确化 | "你提到'大概是这样'——能再精确一点吗？书中哪部分让你有这个感觉？" — 手挥词是思考未到位的信号，温和地要求回到文本 |
| **术语覆盖**（用大词但不解释含义） | 要求定义 | "你用了'X'这个词——在这本书的语境里，作者是怎么定义它的？你的理解和作者的定义一致吗？" — 用术语替换理解是最常见的伪理解形式 |

### 4.5 追问角度参考

当需要追问但不确定方向时，可参考以下认知操作（非强制，自然使用即可）。与 §4.4 的"回答→策略"映射互补，本表提供"阶段→可用角度"的映射：

| 角度     | 作用                                | 何时自然触发   |
| -------- | ----------------------------------- | -------------- |
| 澄清概念 | "你说的X具体指什么？"               | 回答用了模糊词 |
| 质疑假设 | "这里的前提一定成立吗？"            | B阶段批判分析  |
| 追索证据 | "书中哪个部分支持这个看法？"        | 回答无文本依据 |
| 转换视角 | "如果站在对立面看呢？"              | 回答过于单一   |
| 推演后果 | "如果这个观点成立，那Y也应该成立？" | D阶段超越书本  |
| 反思自身 | "你这么想，有没有被什么偏见影响？"  | C阶段个人共鸣  |

## 5. 问题深度递进

> **本章要点**：提问遵循由浅入深的自然递进——从"读了什么"到"想得如何"，再到"与我何干"，终至"超越书本"。阶段转换由目标达成驱动，而非固定题数。

book-grill 的问题分为四个递进阶段：

| 阶段           | 名称     | 认知深度 | 阶段目标                               |
| -------------- | -------- | -------- | -------------------------------------- |
| A 理解确认     | 回忆复述 | 浅→中    | 确认用户准确把握书中核心内容           |
| B 批判分析     | 分析评价 | 中→深    | 引导用户审视结构/论证/立场             |
| C 个人共鸣     | 联系自身 | 深       | 帮助用户建立书中内容与自身的连接       |
| D 超越书本     | 认知迁移 | 超深     | 引导用户将阅读收获延伸到更广的思考/行动 |

**阶段转换机制**：每个阶段有明确的**进入下一阶段条件**（见各类型模板）。当条件满足时自然推进，不固定题数——一个阶段可能只需 1 个问题，也可能需要 5 个。LLM 根据用户回答质量判断是否达成阶段目标，而非机械地走完预设问题序列。

**提问生成方式**：LLM 基于模板中的**提问方向**动态生成问题，每次根据用户上一轮回答选择最合适的方向深入。模板中的**备选问题**仅在 LLM 不熟悉该书时作为兜底使用。

**D 阶段设计意图**：

D1 统一为同一认知任务："这本书带给你的认知变化，会如何影响你未来的思考或行动？"——从书中超越到书外，聚焦认知变化对未来的实际影响。

各类型的**追问方向**不同，但 D1 本身是同一个问题：

- **fiction**：追问核心启示的世界影响
- **nonfiction/technical**：追问前后认知变化（认知闭环）
- **biography**：追问拷问式反思方法对理解的影响（元认知）

这种统一消除了"泄漏抽象"——用户在不同类型下体验的是同一认知深度的 D 阶段，只是追问方向自然不同。

## 6. 待探索追踪

> **本章要点**：标记待探索项不是"用户没答对"，而是识别阅读中值得关注的知识/思维缺口。

### 6.1 什么是待探索项

用户回答"不知道""没想过""说不清楚"的问题。

### 6.2 待探索处理逻辑

```
用户说 "不知道" / "没想过" / "说不清楚"
  → LLM 标记该题为待探索项
  → 温和进入下一题（不超过1次追问）
  → 笔记中该题标记为「待探索」
```

**D1 pass 回退**：如果用户在 D1 说"不知道"/"pass"，跳过 D1 追问，直接进入 closing 问题（"用一句话总结这本书对你的意义"）。D1 pass 不代表反思失败——closing 问题自然收束整个对话。

### 6.3 待探索项在笔记中的展示

```markdown
## 待探索方向

以下问题你未能即时回答，可能是值得进一步思考的方向：

- **作者的核心论点是什么？** — 待探索标记
  💡 提示：试着翻回书中目录，看看作者在导言部分已经明确陈述了写作目的。
- **你会因为这本书改变什么实际行为？** — 待探索标记
  💡 提示：这个问题不需要"正确答案"，哪怕一个微小的习惯改变也值得记录下来。
```

## 7. 双阶段产出：实时札记 + 读后感

> **本章要点**：book-grill 产出两种文件——读后感（对话结束后生成，完整反思）和实时札记（Phase 2 增加，对话中追加追踪待探索项）。

### 7.1 设计思路

|              | 读后感（note）                      | 实时札记（notepad，Phase 2） |
| ------------ | ----------------------------------- | ---------------------------- |
| **更新时机** | 对话结束后一次性生成                | 对话中，每阶段完成后追加     |
| **记录对象** | 完整的阅读反思                      | 用户的待探索项/模糊点/浅思考 |
| **用途**     | 最终产出物，可回溯                  | 对话中的记忆辅助 + 制造张力  |
| **写入方式** | overwrite（覆盖，但文件名带时间戳） | append（追加）               |
| **存储位置** | `notes/<书名>-YYYY-MM-DD.md`        | `notepads/<书名>.md`         |

Phase 1 只生成读后感。读后感中包含"待探索方向"章节，汇总对话中的待探索项。Phase 2 增加实时札记，在对话过程中追加写入 notepad 文件，提供记忆辅助和张力驱动。

### 7.2 实时札记（Phase 2，对话中更新）

#### 更新触发

每个**阶段（A/B/C/D）完成后**，LLM 检查是否需要追加一条札记。触发条件：

```
用户完成了某一阶段的所有问题（阶段目标达成）
  → 回顾该阶段的回答
  ├─ 存在「不知道」/「没想过」的回答 → 追加：「待探索: [问题]」
  ├─ 存在模糊/前后矛盾的回答 → 追加：「模糊: [问题] - 回答摘要」
  ├─ 存在非常浅的回答（< 10 字） → 追加：「浅思考: [问题] - 回答摘要」
  └─ 所有回答深入有见地 → 不追加
```

#### 札记格式

append 写入 `notepads/<书名>.md`，每次更新追加一行：

```
【待探索】A3: 作者在叙事手法上有什么特别之处？— 用户说"没注意"
【模糊】B1: 故事探讨的深层主题？— 用户提到"黑暗森林"但说不清和现实的关系
【浅思考】C1: 有联想到自己的经历吗？— 回答"没有"
```

#### 对话中的使用

LLM 在提问时参考札记：

- 如果用户之前对某类问题答得浅 → 后续同类问题可以更耐心引导
- 如果用户之前对某个具体话题表现出兴趣 → 可以在后续追问中关联

### 7.3 读后感（对话结束后生成）

#### 触发时机

用户输入"结束"或完成全部问题后生成。

#### 读后感格式

```markdown
---
title: <书名>
author: <作者，可选>

<从对话中提取的 C 类回答摘要>

## 超越书本

<从对话中提取的 D 类回答摘要>

<closing 回答>

## 关键问答摘录（知识卡片）

<对话中用户回答最精彩的 1-3 条，以卡片形式呈现>

### 卡片 1：核心观点
```

**INDEX.md 示例**（Phase 2，按需生成，非自动维护）：

```markdown
# 读书笔记索引
```

### 7.5 对话中断处理

- **OpenCode**：Session 持久化，用户重新打开 session 可继续对话
- **其他环境**（Cursor、Claude Code）：对话可能丢失

**Phase 2 增强方案**：在 notepad 文件头部记录会话状态：

```

```

下次 `/book-grill <书名>` 时检查是否存在未完成会话，提示用户是否继续。

Phase 1 不实现 notepad，因此不包含会话恢复机制。

## 9. 信息源策略

### 9.1 设计原则

**Phase 1 不使用 websearch**。LLM 基于用户提供的书名和补充信息推断类型。如果用户只给书名不给简介，LLM 直接用类型推断 + 通用问题开始，用户随时可补充信息。

### 9.2 信息获取链路（Phase 1）

```
用户触发 /book-grill <书名>
  │
  ├─ 用户提供了补充信息（简介/感受/笔记）？
  │   └─ 是 → 使用用户信息，推断类型，进入对话
  │
  └─ 否 → LLM 基于书名推断类型，进入对话
           （用户随时可补充信息，LLM 据此调整）
```

### 9.3 背景收集（条件触发）

类型确认后，LLM 评估自身对该书的熟悉程度。如果 LLM 不自信（无法针对该书内容生成有针对性的问题），则从用户处快速收集背景信息：

```
LLM 不熟悉该书？
├─ 是 → 询问用户书的大致内容 → 提取关键信息 → 确认理解 → 进入提问
└─ 否 → 直接进入提问
```

**目的**：动态提问需要上下文。没有背景信息，LLM 只能使用模板中的备选问题，提问质量下降。

### 9.4 知识锚定（LLM 自身知识受控调用）

对话过程中，LLM 可偶尔（每轮最多一次）引入与书中内容相关的外部知识来制造新的思考角度：

- **不是给答案，而是给一个新的思考入口**
- **严格边界**：引入后必须追问、不确定的知识不引入、每轮最多一次
- **不等于 websearch**：这是 LLM 自身知识库的受控调用，不涉及外部搜索

**关键约束**：

- Phase 1 不依赖 websearch，减少错误面（搜到电视剧而非书等）
- 用户提供的信息 + LLM 自身知识是 Phase 1 的信息源
- websearch 集成推迟到 Phase 3（可选），届时增加源确认步骤

## 10. 对话控制

### 10.1 控制方式

| 输入                         | 行为                       |
| ---------------------------- | -------------------------- |
| "跳过" / "下一个" / "next"   | 跳过当前题，进入下一题     |
| "结束" / "done" / "就到这里" | 终止对话，生成读后感       |
| "不知道" / "pass" / "没想过" | 标记为待探索项，进入下一题 |

### 10.2 进度提示

每轮 LLM 输出附带当前阶段，只显示阶段名，不显示题号和待探索项计数：

```
【阶段: 理解确认(A)】
```

**设计意图**：不显示题号/进度/计数——读者应该自由地深入思考，而不是赶进度。阶段名提供方向感即可。

### 10.3 连续浅回答安全网

如果用户连续 3+ 次回答质量过浅（模糊/手挥/术语覆盖），LLM 应主动参考 strategies.md 中的追问策略（§4.4/§4.5）进行引导，而非放任对话停留在表面。这是对话质量的防御性规则。

## 11. 用户交互流程

### 11.1 全流程

```
触发 → 类型确认（1 轮） → 背景收集（条件触发） → 深度提问（四阶段，动态推进） → 收尾产出
```

### 11.2 详细步骤

**步骤 1：触发**

```
/book-grill 三体
```

或带补充信息：

```
/book-grill 三体 这是一部关于外星文明入侵地球的科幻小说
```

**步骤 2：类型确认（1 轮）**

LLM 推断书类型，用户确认或纠正：

```
我判断《三体》是一本科幻小说(fiction)，对吗？
[对 / 不对，应该是...]
```

用户确认后，LLM 简要说明提问流程：

```
接下来我会从四个维度向你提问：
1. 理解确认
2. 批判分析
3. 个人共鸣
4. 超越书本

每个维度我会根据你的回答自然推进，随时可以说 "跳过" 或 "结束"。
```

**设计意图**：类型确认只需 1 轮。流程说明无需用户额外确认——用户直接开始回答第一个问题即可。不再预告固定题数，因为实际提问数量由对话自然流动决定。

**步骤 3：背景收集（条件触发）**

类型确认后，LLM 评估自身对该书的熟悉程度：

```
LLM 对该书内容/主题/核心论点有信心？
├─ 是 → 跳过背景收集，直接进入深度提问
└─ 否 → 询问用户：
    "在开始之前，能简单说说这本书讲了什么吗？你印象最深的部分是什么？"
    → 提取关键信息（主题、核心论点/情节、作者立场）
    → 确认："我理解这本书主要是在讲 [X]，对吗？"
    → 根据用户纠正调整
```

**设计意图**：背景收集是动态提问的前提——没有上下文，LLM 无法生成针对性问题，也无法判断回答质量。但仅在不熟悉该书时触发，避免对知名经典浪费用户时间。

**步骤 4：深度提问**

按对应书类型模板 + 四阶段递进，**动态生成问题**：

```
A 阶段 → 基于提问方向生成问题 → 用户答 → 追问（1-2 轮）→ 标记待探索项（如有）
  → 继续生成问题或判断阶段目标已达成 → 进入 B
B 阶段 → 基于提问方向生成问题 → 用户答 → 追问（1-2 轮）
  → 判断阶段目标已达成 → 进入 C
C 阶段 → 基于提问方向生成问题 → 用户答 → 追问（1-2 轮）
  → 判断阶段目标已达成 → 进入 D
D 阶段 → 基于提问方向生成问题 → 用户答 → 追问（1-2 轮）
  → 进入 closing
closing（"用一句话总结这本书对你的意义"） → 用户答
```

**关键规则**：
- 每次只问一个问题，等用户回答后再继续
- 问题基于用户上一轮回答动态生成，不机械跟随预设序列
- 阶段转换由**阶段目标达成**驱动（见各类型模板的"进入下一阶段条件"），而非固定题数
- 一个阶段可能只需 1 个问题，也可能需要 5 个——让对话自然流动
- LLM 不熟悉该书时，使用模板中的备选问题作为兜底

**步骤 5：收尾产出**

1. 生成**读后感**，写入 `~/.local/share/book-grill/notes/<书名>-YYYY-MM-DD.md`
2. Phase 2：札记文件保留在 `~/.local/share/book-grill/notepads/<书名>.md`，不删除
3. Phase 2：INDEX.md 不自动更新，用户需要时通过 `/book-grill --index` 按需生成

## 12. 目录结构

### 技能目录

```
~/.agents/skills/book-grill/
├── SKILL.md              # 入口（167 行）：对话流程、角色定义、背景收集、阶段控制、产出格式
├── templates/            # 书类型问题模板
│   ├── fiction.md        # Fiction 阅读策略 + 四阶段提问框架（阶段目标/提问方向/追问示例/备选问题/进入条件）
│   ├── nonfiction.md     # Nonfiction 阅读策略 + 四阶段提问框架
│   ├── biography.md      # Biography 阅读策略 + 四阶段提问框架
│   └── technical.md      # Technical 阅读策略 + 四阶段提问框架
└── strategies.md         # 追问策略表（8 种） + 待探索处理逻辑 + 追问角度参考
```

**拆分原则**：

- SKILL.md 167 行，包含核心流程控制、角色定义和产出格式定义。现有多文件 skill 的 SKILL.md 范围：81 行（improve-codebase-architecture）到 236 行（mcp-builder），167 行在合理范围
- 问题模板拆到 `templates/`，LLM 确认书类型后读取对应模板文件。每个模板包含阅读策略、四阶段提问框架（阶段目标、提问方向、追问示例、备选问题、进入下一阶段条件）
- 追问策略是跨类型共享逻辑，独立为 `strategies.md`，包含 8 种苏格拉底式追问策略和追问角度参考
- **文件引用方式**：使用 `@` 前缀（如 `@./templates/fiction.md`）——OpenCode 的 `resolveFileReferencesInText()` 支持此语法，实测 Markdown 链接引用不被 LLM 主动读取，因此统一使用 `@` 前缀

### 运行时数据目录

```
~/.local/share/book-grill/
├── notes/                 # 读后感（对话结束后生成，带时间戳）
│   └── <书名>-YYYY-MM-DD.md
└── config.json            # 用户配置（可选）
```

## 附录：术语表

| 术语               | 解释                                                                                |
| ------------------ | ----------------------------------------------------------------------------------- |
| **札记**           | 对话中实时记录的待探索项/模糊点/浅思考，append 写入 `notepads/<书名>.md`（Phase 2） |
| **读后感**         | 对话结束后生成的结构化笔记，overwrite 写入 `notes/<书名>-<日期>.md`                 |
| **待探索方向**     | 用户回答"不知道""没想过""说不清楚"的问题，阅读中值得关注的知识/思维缺口             |
| **frontmatter**    | 文件头部的元数据（YAML 格式），包含 title、author、type、date、tags 等字段          |
| **软分类**         | 不追求精准分类，以用户共识为准的分类方式                                            |
| **苏格拉底式诘问** | 通过层层追问引导用户自己发现认知缺口的提问方法                                      |
| **动态提问**       | LLM 基于模板中的提问方向和用户上一轮回答实时生成问题，而非使用固定问题序列          |
| **知识锚定**       | LLM 受控引入外部相关知识制造新思考角度，每轮最多一次，引入后必须追问                |
| **背景收集**       | LLM 不熟悉该书时，从用户处快速收集书籍内容/主题/核心论点，为动态提问提供上下文      |
